# dusk — your daily ritual

A serene personal journaling app. Sage-and-cream theme, serif titles, mood
tracking, habits, a running writing streak, and a full export/backup
system — backed by a real account and a Postgres database, so your journal
follows you across devices and browsers.

## Architecture

- `src/` — React + TypeScript + Vite frontend, deployed as a static site
  (GitHub Pages). Talks to the backend over `VITE_API_URL`.
- `server/` — Node + Express + Postgres backend (email/password auth,
  JWT bearer tokens). Owns all persistence: entries, media, habits, todos,
  settings, and the AI proxy.

The PWA shell still installs and loads offline, but editing/saving requires
connectivity — data now lives on the server, not just in the browser.

## Getting started (frontend)

```bash
npm install
npm run dev
```

By default the dev server talks to a backend at `http://localhost:4000`
(see `server/README` below). Set `VITE_API_URL` in a `.env` file to point
elsewhere.

## Getting started (backend)

```bash
cd server
npm install
cp .env.example .env   # fill in JWT_SECRET at minimum
npm run dev
```

Leave `DATABASE_URL` unset for local development — an embedded Postgres
(`pglite`) is used automatically, persisted to `server/.pglite-data/`. Set
`DATABASE_URL` to a real Postgres connection string (e.g. from Neon) for
staging/production; the same SQL runs against both.

## Scripts

- `npm run dev` — start the frontend dev server
- `npm run build` — type-check and build for production (`dist/`)
- `npm run preview` — serve the production build locally
- `npm run test` — run the vitest unit tests (streak calculation, Hinglish
  translation matching)
- `server: npm run dev` — start the backend with auto-restart on change
- `server: npm test` — run backend unit tests

## AI features

Both "✨ Continue my thought" and "Aa Translate Hinglish" are proxied
through the backend (`/api/ai/*`), which holds a single shared Anthropic
API key server-side (`ANTHROPIC_API_KEY`) — no per-browser key entry
needed. The fallback chain per request:

1. Claude, if `ANTHROPIC_API_KEY` is set on the server (best quality).
2. For translation only: a free public translation API, used automatically
   when no key is configured.
3. A small local phrase bank / word dictionary — used by the backend as a
   last resort, and by the frontend directly if the backend itself is
   unreachable (tagged "offline translation"/"offline suggestion" in the
   editor when this tier is used).

## Data & backups

Use the **Export diary** button to:

- Export a date range as a formatted, printable PDF.
- Export a complete portable backup (`.json`, includes all entries, habits,
  todos, settings, and media as embedded base64 blobs) — importable from
  Settings into this or any other account. Import always mints fresh ids on
  restore, so it's always safe regardless of which account created the file.

## Deploying

- **Frontend**: GitHub Actions (`.github/workflows/deploy.yml`) builds and
  publishes to GitHub Pages on every push to `main`. Set a `VITE_API_URL`
  repository variable (Settings → Secrets and variables → Actions →
  Variables) to the deployed backend's URL.
- **Backend**: `server/render.yaml` is a Render blueprint — connect the repo
  on Render and it provisions a free web service. Set `DATABASE_URL` (e.g.
  from a free Neon Postgres project), `ANTHROPIC_API_KEY` (optional), and
  `CORS_ORIGIN` (the deployed frontend's origin) as environment variables;
  `JWT_SECRET` is auto-generated by the blueprint.
